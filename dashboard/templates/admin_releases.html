Publish a release

  1. On the release engineer's machine, with the signing key that never comes here: 
    api/.venv/bin/python scripts/release-sign.py manifest --deb happymining-agent_X.Y.Z_amd64.deb \
    --version X.Y.Z --key <private key> --out <directory>
    It writes manifest.json and manifest.sig.
  2. Upload them here. The signature is checked against the keys above before anything is stored.
    {{ m.csrf_field(csrf) }}
  3. Upload the package itself to the JSON API, not through this page: 
    curl --fail -X PUT {{ api_base }}/releases/X.Y.Z/artifact \
    -H "Authorization: Bearer <session token>" \
    -H "Content-Type: application/octet-stream" \
    --data-binary @happymining-agent_X.Y.Z_amd64.deb

    Why: a form posted to this dashboard is limited to 1 MiB by the server's body-size limit, and a package is far larger. PUT /api/v1/releases/<version>/artifact is the one route allowed a large body (up to {{ max_bytes }} bytes, HM_RELEASE_MAX_BYTES); it reads the body as a stream, stops at the size the signed manifest states, and stores nothing unless the size and the SHA-256 match it. The session token comes from POST /api/v1/auth/login with your staff account.

  4. Once the package is in (status ready), choose its channels above. A release can be withdrawn at any time; updates not yet handed to a machine are then cancelled.
